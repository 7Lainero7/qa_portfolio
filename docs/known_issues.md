# Known Issues & Resolved Bugs

## ✅ RESOLVED: PATCH /api/expenses/{id} с `{"category": null}` вызывал 500 Internal Server Error

**История:** При попытке передать `null` в поле `category` через PATCH-запрос, валидатор пропускал значение, и SQLAlchemy пыталась записать `NULL` в колонку с ограничением `NOT NULL`, что приводило к `IntegrityError` (500).  
**Решение:** В `schemas.py` добавлена явная проверка `if value is None: raise ValueError(...)`. Теперь API корректно возвращает `422 Unprocessable Entity` с понятным сообщением об ошибке.

## 🟡 OPEN: Тихая нормализация пустых строк в `category`

**Severity:** Low  
**Priority:** P3  

**Описание:**  
Если при создании или обновлении расхода передать `{"category": "   "}` (только пробелы), API не возвращает ошибку валидации. Вместо этого валидатор выполняет `strip()`, видит пустую строку и молча заменяет её на дефолтное значение `"other"`.  

**Ожидаемое поведение (строгое):**  
Возврат `422 Unprocessable Entity`, так как клиент явно передал невалидное значение, а не опустил поле.  

**Фактическое поведение:**  
`200/201 OK` с `category="other"`.  

**Комментарий:**  
Это поведение зашито в текущей логике валидатора (`return value if value else "other"`). Для пет-проекта это допустимый компромисс (DX), но в строгом финтехе это должно быть `422`. Тест на это поведение намеренно не добавлен, чтобы не фиксировать "баг" как ожидаемое поведение, пока он не будет исправлен архитектурно.
